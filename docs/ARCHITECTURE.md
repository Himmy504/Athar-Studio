# Architecture

## Application boundary

The React renderer owns the editor state and generates ASS/SRT documents. Tauri commands invoke native Rust storage, model, media, and rendering services. The renderer cannot execute arbitrary shell commands. Gemini is opened in the user's external browser; there is no embedded remote website, background upload, API key, or cloud account.

The project has five main code areas:

- `src/domain.ts`: project parsing, immutable edits, Gemini contract, review rules, split/merge, and approval validation.
- `src/subtitles.ts`: one ASS document used for both preview and native video rendering; SRT output and readability hints.
- `src/App.tsx` and UI components: creator workflow, dialogs, playback, source selection, review, typography, backgrounds, and branding.
- `src-tauri/src/`: background job control, model verification/download, media preparation, atomic storage, and export.
- `scripts/`: reproducible asset/runtime preparation and integration QA.

## Native commands

| Command | Inputs | Result |
| --- | --- | --- |
| `import_media` | source path, job ID | duration, video properties, proxy path, waveform |
| `transcribe` | source path, excerpt bounds, model ID, auto/CPU device, job ID | Arabic segments and actual processing backend |
| `runtime_status` | none | installed binaries, memory, available/installed models |
| `download_model` | allowlisted model ID, job ID | verified local installation |
| `cancel_job` | active job ID | cooperative cancellation, waiting for cleanup |
| `save_project` | project JSON, optional destination | saved project JSON |
| `open_project` | path | versioned project JSON |
| `recover_project` | none | recovery JSON and matching saved-project path |
| `path_exists` | local path | file availability |
| `export_project` | project JSON, generated ASS, output path/format, job ID | completed output path |

Native media/model jobs share a single job guard. Child stdout/stderr are drained continuously. Cancellation terminates media processes and stops model HTTP transfers. A failed or cancelled render never replaces the destination with a partial MP4.

## Review state

Each segment keeps immutable original ASR text, the Arabic sent in the latest request, proposed Arabic, current editable Arabic, English, correction notes, separate correction/uncertainty decisions, and an exact-value approval.

The source text and translation are data, including when they contain markup-like characters. ASS overrides are generated by the app; literal braces/backslashes from captions or metadata are neutralized. Timing remains excerpt-relative and comes from the local editor, never Gemini.

Requests are invalidated by source, excerpt, glossary, text, structural, or timing changes. An import is fully parsed and checked before modifying any segment. Earlier response text remains in the project's import history.

## Rendering

`generateAss` controls dimensions, fonts, colors, outlines, positioning, bilingual spacing, emphasis, labels, and phrase fades. The browser uses SubtitlesOctopus with a canvas synchronized to excerpt-relative time. FFmpeg uses libass with the same ASS data and font files.

The font preparation script decompresses the fontsource WOFF2 assets to TrueType. This is necessary because the Windows FFmpeg build does not support loading those WOFF2 fonts directly. Matching TrueType files are bundled for both caption renderers; CSS uses the corresponding WOFF2 for the editor itself.

Rust composes the background, optional logo, and subtitles, maps only the source audio, encodes H.264/AAC, then atomically publishes the completed file. A neutral audio-only project defaults to a gradient. Footage is selectable only when source video exists.

## Persistence and runtime

Project saves use a synchronized atomic temporary-file replacement with a preceding backup. Autosave is serialized. Window closing flushes the latest project and cancels active jobs before destroying the window.

Runtime executables are packaged as Tauri resources. CPU and Vulkan whisper.cpp builds are pinned to upstream `b4938` / commit `371b5a7561823ab2bb32142d2751e35e7534727b`. Model SHA-256 digests are pinned in the native model catalog; changing an upstream model requires explicitly updating that catalog and rerunning tests.

The release does not contain test-only native smoke entry points. Those compile only with the `native-smoke` Cargo feature, and use an isolated data directory beneath the test input.
